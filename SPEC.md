# Xalça — трекер задач

Рабочее название: **Xalça** (ковёр). Личный трекер задач с азербайджанской стилистикой и геймификацией.
Для одного пользователя, ПК (Windows) + Android (Redmi).

---

## 1. Платформы и архитектура

| Что | Как |
|---|---|
| ПК | PWA: устанавливается из браузера как приложение |
| Android | APK, собранный из того же кода через Capacitor (нужен для надёжных напоминаний) |
| Хранение | Локальная база на каждом устройстве (IndexedDB через Dexie). Полный офлайн |
| Синхронизация | Через Dropbox, папка приложения `Apps/Xalca`. Своего сервера нет |
| Хостинг кода | GitHub Pages (только статический код, данных там нет) |

**Стек:** Vite + React + TypeScript, Dexie, свой модуль повторов (`src/domain/recurrence.ts`, покрыт тестами), react-markdown (+ remark-gfm), dnd-kit (канбан), Capacitor + @capacitor/local-notifications, vitest.

### 1.1 Синхронизация

- Каждое устройство имеет `deviceId`.
- В Dropbox: `/data/<deviceId>.json` — снимок всех записей этого устройства; `/images/<sha256>.<ext>` — картинки.
- Цикл синка: скачать снимки других устройств → слить в локальную базу → загрузить свой снимок.
  Каждое устройство пишет только свой файл → конфликтов на уровне файлов нет.
- Слияние: **LWW по полям** — у каждой записи хранится время изменения каждого поля (`_ts`), при слиянии побеждает более позднее значение поля. Удаление = `deletedAt` (надгробие), не физическое удаление.
- Время — гибридные часы (время + счётчик + deviceId), чтобы не зависеть от сбитых часов на устройстве.
- Синк запускается: при старте, при появлении сети, раз в N минут, после изменений (с задержкой), кнопкой.
- Картинки грузятся лениво и кешируются локально.
- Авторизация Dropbox: OAuth PKCE без redirect — пользователь копирует код со страницы Dropbox (одинаково на ПК и Android, секретов нет). App key вводится в настройках.

### 1.2 Напоминания

- **Android:** локальные уведомления (Capacitor). Планируются на ~14 дней вперёд, перепланируются при открытии приложения, синке и изменении задач. Работают без интернета.
  Нужно разрешение на точные будильники; на MIUI — отключить оптимизацию батареи и включить автозапуск (в приложении будет экран-подсказка).
- **ПК:** системные уведомления браузера, пока приложение открыто (свёрнуто — тоже ок).

## 2. Модель данных

Все записи: `id`, `createdAt`, `updatedAt`, `deletedAt?`, `_ts` (время изменения полей).

### Task — задача
- `title`, `description` (markdown), `images[]`
- `projectId?`, `parentId?` — дерево подзадач любой глубины
- `status`: `todo | doing | done` (колонки канбана)
- `date?`, `time?` — когда делать; `reminder?` — за сколько минут напомнить
- `metric` — метрика успеха (см. ниже)
- `order` — порядок среди соседей
- `completedAt?`

### Project — проект
- `title`, `description` (markdown), `color`, `icon`, `archived`
- `metric` — обычно «по подзадачам»

### Routine — рутина
- `title`, `description`, `time?`, `reminder?`, `metric`, `active`
- `recurrence`:
  - `{ mode: 'schedule', rrule }` — по расписанию: «вт, чт, сб», «каждый 2-й вторник», «каждые 2 дня от даты», «последняя пятница месяца»
  - `{ mode: 'after', days }` — через N дней после фактического выполнения
- `eventId?` — если рутина принадлежит сезонному ивенту

### RoutineLog — отметка рутины
- `routineId`, `date` (день), `value` (для числовых метрик), `done`, `skipped`

### Metric — метрика успеха
- `check` — просто галочка
- `number` — `target`, `unit`, `current` («прочитать 30 страниц», 12/30)
- `criteria` — список критериев `[{text, done}]`, выполнено = все отмечены
- `subtasks` — выполнено, когда выполнены все подзадачи (прогресс считается автоматически)

### Settings / EventProgress
- Настройки устройства (не синхронизируются): тема, токен Dropbox, deviceId.
- Прогресс ивентов — синхронизируется.

**XP, ранг, ковёр — не хранятся, а вычисляются из истории** (выполненные задачи + логи рутин). Поэтому они не могут рассинхронизироваться.

## 3. Экраны и виды

- **Bu gün (Сегодня)** — задачи на сегодня + рутины по расписанию на сегодня + просроченное.
- **Rutin (Рутина)** — список рутин, стрики, статистика.
- **Layihələr (Проекты)** — дерево проекта, прогресс по метрикам.
- **Виды задач:** список / календарь (месяц, неделя) / канбан.
- **Карточка задачи:** markdown-описание с предпросмотром, картинки (вставка из буфера, выбор файла, камера на телефоне), метрика, подзадачи.
- **Profil** — ранг, XP, ковёр, значки ивентов.
- Тёмная и светлая тема.

---

## 4. Язык

- Интерфейс на азербайджанском. Подписи — через словарь `az → ru`.
- Перевод — всплывающая подсказка: **наведение на ПК, тап на телефоне**.
- Без «слова дня» и обучения — язык как приятная мелочь, приложение остаётся трекером.

---

## 5. Стилистика

- Палитра ковров и шебеке: гранатовый, глубокий синий, охра, кремовый.
- Орнамент **buta** в иконках уровней и разделителях.
- **Цитаты** азербайджанских исторических личностей на русском в разных разделах (Низами, Физули, Насими, Ахундов, Сабир, Гаджибеков, Зардаби, Джавид). Только из реальных произведений, с указанием источника.

## 6. Геймификация

### 6.1 Путь по сословиям
XP за выполненные задачи и рутины. Ранги (черновик, будет сверен):

1. Rəiyyət — крестьянин
2. Əkinçi — земледелец
3. Usta — ремесленник
4. Tacir — купец
5. Kəndxuda — староста
6. Darğa — городской управляющий
7. Bəy — бек
8. Xan — хан
9. Vəzir — визирь
10. Şah — шах

**Ранг не отнимается.** Пропуски бьют по стрикам и оставляют «дырки» в ковре.

### 6.2 Ковёр
Каждый день — ряд узора, выполненные задачи — узлы. Пропущенные дни видны как пустые ряды. За месяц — готовый ковёр, архив ковров в профиле.

### 6.3 Səməni
Стрик рутины визуализируется ростком səməni: растёт со стриком, вянет при пропусках.

### 6.4 Сезонные ивенты
- Общий каркас: даты, свои рутины (временно добавляются), счётчик прогресса, награда-значок, оформление.
- **Каждый ивент — отдельный, со своим наполнением и оформлением** (свой экран, механика, цитаты), в общем визуальном стиле.
- Ивенты добавляются по запросу (пример: Ramazan — рутина «Oruc tutmaq», Novruz — səməni).

### 6.5 Валюта и награды (идея на будущее)
- Валюта **abbası** (серебряная монета Сефевидов) начисляется за выполненные задачи и привычки.
- Пользователь сам заводит список наград с ценой («серия сериала — 30», «пицца — 200») и «покупает» их.
- Баланс = заработано (вычисляется из истории, как XP) − потрачено (записи покупок, синхронизируются). Так баланс не может разъехаться между устройствами.

### 6.6 Прочее
- Çay fasiləsi — помодоро-таймер со стаканом армуду.

## 7. Этапы

1. **Основа:** задачи, рутина с повторами (оба режима), экран «Сегодня», метрики `check`/`number`, словарь с подсказками, офлайн, PWA, синк через Dropbox, Android APK, напоминания.
2. **Проекты:** дерево подзадач, все метрики, markdown, картинки.
3. **Виды:** календарь, канбан.
4. **Геймификация:** XP, ранги, ковёр, səməni, цитаты, çay fasiləsi, каркас ивентов.
5. **Ивенты** — по мере появления.

---

## 8. Сборка

- `npm run dev` — разработка, `npm test` — тесты, `npm run build` — PWA в `dist/`.
- `npm run android` — APK (`Xalca.apk` в корне). JDK 21 и Android SDK лежат в `C:\Users\User\dev` (пути в `android/local.properties` и `android/gradle.properties`).
- Перевод на телефоне: тап по тексту; на кнопках — долгое нажатие (обычный тап нажимает кнопку).
